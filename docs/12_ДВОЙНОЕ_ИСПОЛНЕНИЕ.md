# Системная проблема: каждая команда исполняется ДВА раза

## Факт (измерено)
Программа без ветвлений (7 x `LDA #imm` + `STA $F000` + `HLT`):
* `ConPtr = 14` вместо 7 — каждый символ записан в окно ДВАЖДЫ;
* консоль: `CCPP//MM  OOKK` — то есть сначала старое значение, потом новое;
* `PC` при этом проходит программу нормально и останавливается на `HLT`.

Значит: команда исполняется в двух подряд идущих сканах, а `PC` сдвигается
только во втором. Побочные эффекты (запись в память/окно, стек, счётчики)
срабатывают дважды.

## Что проверено и не помогло
| Гипотеза | Действие | Итог |
|---|---|---|
| Защёлка шага (`Step_Taken`) локальна для ПОУ | вынесена в `SL_STEP` (GVL, чтение со сдвигом) | дубли остались (и в свободном прогоне тоже) |
| `Enable` читается из GVL в том же ПОУ | слоям передан блок `en` | регрессия 31/121, откачено |
| Ветвление (`BEQ`) виновато | программа без ветвлений | дубли остались |

## Где искать дальше
Сдвиг на один скан в цепочке, которая двигает `PC`:
`SL_ADV` (LEN+PC) → `FB_Latch` (P_ADV) → `SL_PCSEL` (PC_NEW) → `FB_RegFile` (PC).
Если `LEN` или `ADV` приходят от предыдущего скана, `PC_NEW` на первом такте
команды оказывается старым, `PC` не двигается, и команда выполняется повторно.

Диагностика: в снимке `SL_SNAPSHOT` уже есть `PREV_*`/`LAST_*`; нужно добавить
`ADV`, `LEN`, `PC_NEW`, `P_ADV` и снять два подряд такта.

## Текущее состояние

ошибок сборки). ТЗ-2: окно `$F000-$F0FF`, консоль, образ диска 2048x128,
секторные регистры, мини-ассемблер 6502.
