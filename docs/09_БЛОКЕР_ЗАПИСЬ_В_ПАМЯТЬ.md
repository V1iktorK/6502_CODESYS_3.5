# БЛОКЕР: запись в массив по индексу-переменной

## Что проверено (экспериментально, в этой среде CODESYS 3.5 SP17 Patch 3)

| Форма записи | Где | Результат |
|---|---|---|
| `GVL_MEM.Mem[1024] := ...` | внутри вложенного ПОУ (`SL_STWRITE`) | **работает** |
| `GVL_MEM.Mem[GVL_CPU.WR0] := ...` | внутри вложенного ПОУ | **не работает** (тихо) |
| `GVL_MEM.Mem[GVL_CPU.WR0] := ...` | в программе `PLC_PRG` | **не работает** (тихо) |
| `GVL_MEM.Mem[ADR0] := ...` (`ADR0` — локальная переменная программы) | в программе | **не работает** (тихо) |
| `GVL_MEM.Mem[ADR0] := ...` (`ADR0` — входной пин ПОУ) | во вложенном ПОУ | **не работает** (тихо) |

Ошибок компиляции нет ни в одном варианте; значение просто не появляется в
массиве. Это ровно правило **2.4 конспекта**: запись в массив по ВЫЧИСЛЯЕМОМУ
индексу теряется. Чтение по вычисляемому индексу при этом работает (выборка
команд `Mem[PC1]` функционирует).

## Почему это блокер

Без записи в RAM невозможны: `STA/STX/STY`, стек (`PHA/PHP/JSR/RTS/BRK`),
а значит и вся ТЗ-2 (диск, CP/M, загрузка `.COM`). Сейчас из 121 кейса
проходят 113 — все оставшиеся 8 упираются именно в это.

## Варианты решения (в порядке предпочтения)

1. **Проверить ещё формы индекса**: `Mem[ADR0]`, где `ADR0 : INT` (а не `WORD`);
   `Mem[SEL(...)]`; `Mem[ADR0 + 0]`; запись через `inOutVariables`.
2. **Запись через функцию, возвращающую массив**: `F_MemSet(Mem, ADR, VAL)`
   возвращает `ARRAY[0..65535] OF BYTE`, и делается `GVL_MEM.Mem := F_MemSet(...)`.
   Функции, возвращающие массивы, в проекте уже работают (`F_UnpackByte`).
   Минус — копирование 64 КБ за такт.
3. **Двумерный массив с литеральным старшим индексом** (`ARRAY[0..255, 0..255]`):
   если литеральный индекс допустим, старший байт адреса можно разложить
   селектором по 256 ветвям (громоздко, но линейно).
4. Крайний вариант — микро-ПОУ на ST только для `Mem[адрес] := значение`
   (оформляется как согласованное отступление, логика остаётся в FBD).
