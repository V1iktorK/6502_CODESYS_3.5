# ПЛАН ИСПРАВЛЕНИЯ ОШИБКИ C0046

`C0046: Идентификатор 'IoConfigTaskMap' не задан`
`Application [PLCWinNT: Plc Logic]`

---

## 1. ДИАГНОЗ — установленные факты

| Факт | Как проверено |
|---|---|
| Устройство проекта — `PLCWinNT (CoDeSys SP Win V3)` | дерево устройства, лог `fix_ioconfig.py` |
| **В репозитории устройств этой установки `PLCWinNT` ОТСУТСТВУЕТ** | поиск по всем `device.xml` в `%ProgramData%\CODESYS\Devices` — совпадений ноль |
| `CODESYS Control Win V3` — **установлено**, тип `4096` | `devicecache.xml`: `<Name>CODESYS Control Win V3</Name>` |
| `CODESYS Control Win V3 x64` — установлено, тип `4102` | там же |
| Ошибка была в проекте **с самого начала**, до всех правок | первый скриншот заказчика |
| Программная замена устройства невозможна | в Scripting API **нет** `add_device`; у объекта устройства нет методов `replace` / `set_device_identification` |

### Механизм ошибки

Проект создаётся из шаблона `Templates\Standard.project`, который ссылается на
устройство `PLCWinNT` — legacy-устройство старой линейки CoDeSys SP Win V3.
**Описания этого устройства в данной установке CODESYS нет.** Компилятор не может
разрешить ссылку на конфигурацию ввода-вывода устройства и выдаёт
`C0046: Идентификатор 'IoConfigTaskMap' не задан`.

**Следствия, важные для выбора пути исправления:**

1. Это **не ошибка схем, не ошибка логики и не моих правок**. Ни одна из 21 схемы
   к ней отношения не имеет — `check_static.py` даёт 0 замечаний.
2. **«Обновить устройство» не поможет** — обновлять нечего, описания нет.
3. Правка параметров устройства тоже не поможет — нечего править.
4. Работает только **замена устройства на установленное**.

## 2. ПЛАН ИСПРАВЛЕНИЯ

### Шаг 1. Сменить устройство на `CODESYS Control Win V3` (тип 4096) — основной путь

1. Открыть `C:\Users\Ольга\OneDrive\Рабочий стол\CODESYS\CPM6502\build\CPM6502.project`
2. В дереве устройства найти узел **`PLCWinNT (CoDeSys SP Win V3)`** (самый верхний под проектом)
3. **Правый клик** по нему → **«Изменить устройство…»**
   *(если пункта нет — двойной щёлчок по узлу, вкладка «Общие», кнопка «Изменить устройство…» внизу)*
4. В списке выбрать **`CODESYS Control Win V3`** (без «x64» — тип 4096)
5. ОК. CODESYS предложит сохранить соответствие переменных — согласиться
6. `F11` — пересборка

**Почему это сработает:** `CODESYS Control Win V3` — установленное описание
(тип 4096), у него нет legacy-конфигурации ввода-вывода, из-за которой возникает
`IoConfigTaskMap`. Это штатное устройство для симуляции; позже оно меняется на
`CODESYS Control for Raspberry Pi` без переделки проекта.

**Проверка успеха:** в окне «Сообщения» **0 ошибок**. Схемы, GVL и POUs
остаются на месте — замена устройства не затрагивает логику приложения.

### Шаг 2. Если «Изменить устройство» недоступно или список пуст

Признак: CODESYS не показывает список устройств или не даёт применить замену.
Тогда — **путь через новый проект**, он гарантирован и не зависит от шаблона:

1. `Файл → Новый проект` → **`Стандартный проект`** → в диалоге выбрать устройство
   **`CODESYS Control Win V3`** → язык **FBD** → имя `CPM6502_v3` → ОК
   *(в новом проекте автоматически появятся `PLC_PRG`, `Taskkonfiguration`, `MainTask`)*
2. Удалить из него пустой `PLC_PRG` (он не нужен: точка входа у нас своя)
3. `Проект → Импорт PLCopen XML` — по очереди 10 файлов из `…\CPM6502\plcopen\`:
   `F_UnpackByte.xml`, `F_PackByte.xml`, `F_Join16.xml`, `F_Split16.xml`,
   `F_Add16.xml`, `FB_Decoder6502.xml`, `FB_IOBridge.xml`, `FB_IRQController.xml`,
   `FB_AnalogBridge.xml`, `FB_DiskImage.xml`
4. Создать 5 GVL (правый клик по `Application` → «Добавить объект» → «Список
   глобальных переменных») с именами `GVL_CPU`, `GVL_MEM`, `GVL_BUS`, `GVL_IO`,
   `GVL_MAP` и вставить в **верхнее окно** каждой объявления из одноимённых
   файлов `GVL_decl.txt`, `GVL_mem_decl.txt`, `GVL_BUS.txt`, `GVL_IO.txt`, `GVL_MAP.txt`
5. `F11`

**Почему надёжнее:** новое устройство задаётся ещё до создания проекта, шаблон
`Standard.project` не используется вообще, `PLCWinNT` не появляется.

**Важно про окна:** объявления переменных — **только в верхнее окно** POU
(раздел `VAR … END_VAR`). В нижнем окне (схема) — только ссылки на эти имена.
Это то самое правило, из-за которого ранее молча не создавались схемы.

### Шаг 3. Если и это не поможет — переустановить описания устройств

Признак: `CODESYS Control Win V3` тоже не выбирается.
Тогда в **CODESYS Installer** (`Пуск → CODESYS → CODESYS Installer`) проверить
установленные пакеты устройств и доустановить `CODESYS Control Win V3`
(входит в состав `CODESYS Control for Windows`). После установки — Шаг 1.

После нуля ошибок — по `docs\02_ПЛАН_ДОВЫПОЛНЕНИЯ_И_ТЕСТЫ.md`:

1. `FB_CPU_Core` — одна оставшаяся гипотеза: сочетание вызова экземпляра FB и
   функций в одной схеме. Пробник: POU, вызывающий и экземпляр, и функцию.
   Если подтвердится — распаковку битов `P` встроить прямо в схему.

3. `FB_BIOS_6502` — монитор (cold/warm boot, консоль, секторы, jump table `$FF00`,
   векторы `$FFFC/FFFD` и `$FFFE/FFFF`).
4. `TEST_6502`, `TEST_CPM_IO` — прогон по плану тестирования.
5. Цикл «фикс → полная регрессия» до нуля ошибок.
6. HMI.

## 3. ЧЕГО ДЕЛАТЬ НЕ НАДО

| Действие | Почему бесполезно |
|---|---|
| «Обновить устройство…» | обновлять нечего: описания `PLCWinNT` в системе нет |
| Правка параметров устройства | нечего править — устройство не разрешается |
| Правка схем и GVL | `C0046` от них не зависит, `check_static.py` — 0 замечаний |
| Удаление `PLCWinNT` без переноса POUs | потеряются все 6 POU и 5 GVL |
| Генерация проекта через `projects.create()` | в этом API нет `add_device`, устройство не добавить |

## 4. ОДНО ДЕЙСТВИЕ, КОТОРОЕ НУЖНО ОТ ЗАКАЗЧИКА

**Смена устройства — операция только для IDE.** Через Scripting API она
недоступна принципиально: метода `add_device` в API нет, у объекта устройства
нет методов замены. Это проверено по полному дампу API, а не предположено.

Достаточно **Шага 1** (6 действий в IDE). Если он не сработает — **Шаг 2**
(новый проект + импорт 10 XML), он гарантирован.

После этого я продолжаю сам: довожу ядро, цепочку, монитор и тесты до полного
отсутствия ошибок, и тогда отчитываюсь.
