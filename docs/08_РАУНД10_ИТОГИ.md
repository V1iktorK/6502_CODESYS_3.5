
# Раунд 10: что выяснено и что осталось

## Проверено экспериментально
* `SEL` в CODESYS: **G=FALSE -> IN0, G=TRUE -> IN1**, пины сопоставляются
  ПО ИМЕНИ (тест `tools/test_sel.py`, результат в `log/test_sel.log`).
  Значит соглашение в генераторах верное, порядок пинов ни при чём.
* Отключение «обхода компараторов» (`USE_WRAP_CMP = FALSE` в `tools/fbd.py`)
  дало +4 кейса: этот обход ставил между `EQ/NE/LT/GT` и потребителем
  локальную переменную и читал её в том же ПОУ (правило 2.5 -> прош��ый скан).
* Ожидаемый PC в тестах надо «парковать» всегда, иначе ядро уходит в нули,
  выполняет `BRK` и портит PC/SP (это давало `PC=0`, мусор в SP).

## Новые ступени (все — отдельные ПОУ, порядок в `FB_CPU_Core`)
`SL_PREP` (сигналы дешифратора + разрешения такта) -> `SL_REGSEL`
(`REG_WR` по `SRC`) -> `SL_STDATA` (`STK_D0`) -> `FB_CPU_Store` ->
`SL_STWRITE` (фактическая запись) ; `SL_CARRY` (перенос через 16-битную сумму);
`SL_NZF`/`SL_VSEL`/`SL_FLG_*` (регистр P по одному биту).

## Остаток (9-10 кейсов) и гипотезы
1. `PHA` (T108) толкает `PCH` вместо `A` -> похоже, `IS_JSR` остаётся TRUE
   от предыдущей команды. Проверка: дамп `IS_JSR`/`SRC`/`REG_WR` в такте.
2. `PHP` (T111) ставит лишний бит `Z` (`$36` вместо `$34`) -> `Z_F2`
   (REG_WR = 0) приходит от прошлого такта.
3. `JMP ($03FF)` (T091, «аппаратный баг страницы») и `RTS` (T093) -> PC=0:
   не формируется косвенная цель/возврат для адресов в странице стека.
4. `STX zp,Y` (T027), `T118`, `T120`, `T121` -> каскад от 1-3.
