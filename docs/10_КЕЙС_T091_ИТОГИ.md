# Итог по кейсу T091 (аппаратный баг страницы JMP ($xxFF))

## Факт
`JMP ($03FF)` даёт `PC = $9950` (вектор читается из `$03FF`/`$0400`),
а должно быть `$0450` (`$03FF`/`$0300`, перенос внутри страницы не делается).
Трассировка по тактам: `PC = [39248, 0, 0, …]` (`39248 = $9950`).

## Почему не удаётся исправить (5 попыток, все откачены)

| Где размещался расчёт переноса | Результат прогона |
|---|---|
| новая ПОУ `SL_INDPA` перед `SL_INDP` (слой адресации) | 109/121 — обнуляются `SP`, `EFF` |
| расширение самой `SL_INDP` (локальная `HIA`) | 109/121 |
| новая ПОУ `SL_INDW` на уровне ядра между S1 и S2 | 111/121 |
| расчёт внутри `SL_SELECT12` (`PAGEW` локально) | 52/121 — рушится вся адресация |
| `SL_INDW` в слое `FB_CPU_Select` (пины `PTR`/`PGB`) | 120/121, но перенос НЕ применяется |
| `SL_INDW` пишет `C_INDW`, селектор читает её | 59/121 |

## Вывод
Любое расширение цепочек «адресация» и «выбор адреса» ломает композицию
(симптом: обнуление `SP`/`EFF`/`REG_WR`). Изменения внутри уже существующих
ступеней тоже не проходят. Единственный вариант — **пересобрать слой выбора
адреса генератором «с нуля»** (единая ПОУ, где режим `ind` сразу считается с
переносом страницы), не наращивая существующие ПОУ.

## Побочные полезные результаты
* `traces`: в стенде есть трассировка `PC` по тактам и снимок сигналов такта
  (`LAST_*`, `PREV_*`, включая `C_ABS`, `C_IND`, `EFF`).
* Подтверждено: `Mem[...]` по переменному индексу **читается** (в том числе из
  ПОУ), а запись требует ST-ПОУ (`FB_MemStore`) — она работает.
